# Manage Products prototype (V2.3)

It is a prototype, not production code: all data is in-memory (`src/data/initialDb.js`) and resets on reload.

Stack: React 18, MUI v6, AG Grid Community v33 (themeQuartz), Vite, JSX. Styling follows PRIZM 3.0 (dark) plus a product layer. Owner: Xinyi (UX/UI designer). She iterates on behaviour/visuals by describing changes and reviewing the published artifact.

## Commands
- `npm install`, `npm run dev` (live), `npm run build` (static site in `dist/`), `npm run lint`, `npm run format`.
- `npm run build:artifact` → `dist-artifact/{index.html, app.js}`: one classic-script bundle for publishing as a claude.ai Artifact.
- Publish: Artifact tool, `url` = the V2.3 artifact (https://claude.ai/artifact/8sEhAjG98T9p4A5WW3c4F8; V2.2 stays at https://claude.ai/artifact/7iX4sbmEcjaVn4b8PUJhN9), `file_path` = `dist-artifact/index.html`, `files` = `{"app.js": "<abs path>/dist-artifact/app.js"}`. Publish only when the user wants to look at something, once per round of changes. Local page needs `<!doctype html>` (the artifact host adds it).
- Checks: `npm install --legacy-peer-deps` (eslint 10 vs eslint-plugin-react peer conflict), then `npm run build && npm run preview` then `python3 scripts/checks/<name>.py` (Playwright; `BASE_URL` env to override). Run only the check for the flow you changed.

## Layout of `src/`
`constants.js` option lists and sizes · `data/initialDb.js` sample data and the db shape · `lib/domain.js` business rules (Fixed pool, pruning, tab dots, validation) · `lib/utils.js` small helpers · `theme/mpTheme.js` ALL tokens, MUI overrides, AG Grid params and global CSS · `theme/index.js` createTheme + grid theme · `components/` shared UI (PickerField multi-select, cells, previews, EditGrid, dialogs) · `mapping/` Mapping list + create/update form · `schedule/` Schedule grid, cells, month nav, legend · `products/` Product Family list, form, fields · `App.jsx` modal shell, tabs, db state.

## Terminology (UI text vs code)
UI text and code use the same names: **Unit / Type / Activity Type / Category** (`unit`, `type`, `activityType`, `category`; sub-tab values `"unit"` / `"activity"`). The Mapping field is **Type - Code**: one dropdown whose options read "O - All", "T/X - All except PREP" and "X - PREP" (labels from `typeCodeLabel` in `utils.js`; field keys O, T/X, X-PREP). Stored data is `type` (O, T/X, X) plus `code` (PREP for X, else null). T/X means Type T and X share the Product Families (all Codes except PREP). In the real system T, X and O are stored separately; the prototype keeps one T/X record, so devs save it as a T and an X record with the same families. Phrases like "Mapped to Type O" are literal. Sample Category values: Category A–D.

## Rules the prototype encodes
- **Type O** Mapping: Activity Type + Categories, each Category links its own Product Families (`links`). Schedule "Activity Type" tab rows = Activity Type × Category pairs, months pick that pair's families.
- **Launcher page**: "Start with" (data preset) sits above the persona tabs; no helper hints. Dummy data: Type O Alpha (Category A: ART KITS, AUTO, BABY; Category B: OFFICE, PET CARE), T/X (BEAUTY, BOOKS, CLOTHES), X - PREP (FRUIT).
- **Personas** (tabs above the launcher, one shared dataset; switching closes the window): **A** full access; **B** edits Schedule only; **C** view only (`PERSONAS` in `constants.js`, `access` from `useUi()`). A tab without edit access has no CTA (no Create button, no Actions column, no "start by creating" text) and its table ends 24px above the modal's bottom edge. Schedule empty states: A keeps the "here" link to Create Mapping; B and C read "No Type T/X Mapping found." (Unit) and "No Type O Mapping found." (Activity Type), no link (`NO_MAPPING_COPY`). Schedule month dropdown options show no "Type ..." line (one Type per tab).
- **Rows and forms**: in the Mapping and Product Family tabs, when the persona can edit, hovering a row turns every cell's text cyan/400 #00DCFF and underlined, except the Mapping Product Family column (its "Category A:" labels and chips stay unchanged), and clicking the row opens its Update form, same as the Edit icon (`.row-link`). The Schedule has no row hover. Update Mapping and Update Product Family have a **Delete** button (`dangerOutline`: outlined red/400) at the far left of the footer, sharing the delete flow with the list icon (`useDeleteMapping`, `useDeleteFamily`). The **FIXED** family (`FIXED_FAMILY`) cannot be deleted (Delete disabled in the list and the form), and in its Update form every Fixed Product's "x" is disabled with the tooltip "Fixed for <Unit> Unit". Disabled icon buttons inside tables keep the default cursor.
- **Date sorting** (Mapping and Product Family lists): Created and Last Updated headers are clickable (`SortHeader`, `useDateSort` in `components/cells.jsx`). Default is Created, newest first. Clicking the active column toggles; clicking the other column sorts it newest first. An outlined arrow 8px right of the active label shows the direction: down = newest first, up = oldest first. Only one column is sorted at a time; the inactive one has no arrow.
- **Type T/X** Mapping (one Mapping; the old Type T and Type X-without-Code are merged): Product Families scheduled per Unit per month.
- **Schedule select** (personas A and B): every month of every row shows the multi-select by default, also after Save (no click-to-edit). Each month cell is the select with no border of its own, only a white 1px line at the bottom of the cell; while its field is active the whole select gets a 2px accent border. A select with fewer chips than its row-mates is centred vertically, so counters line up across the row. Chips stay dark (#2C2C2C) when active, are never truncated, left-aligned and wrap onto new lines; one group on the right = 32px counter (rectangle, radius 4, #FFFFFF 16%) + chevron. Clicking a field activates it (dropdown opens, `swapCount` on `PickerField`): while the user types in the field the counter is replaced by the Clear X (it wipes the typed text); once an option is selected the counter returns. Empty field: placeholder "—" and counter 0. Choices are a draft per row; Cancel / Save in Actions enable only while that row has changes, and leaving the tab, switching Unit / Activity Type or paging months asks to discard unsaved rows. With no Type T/X Mapping the selects still show, and the dropdown holds the empty message: A "No results found. Start by creating a Type T/X Mapping here." (link opens Create Mapping, drafts are restored), B "No Type T/X Mapping found." Persona C sees chips only and no Actions column.
- **Review switch** (temporary): the launcher has a "Schedule" toggle next to "Start with": Version 41 (default, selects always shown, as above) or "Click row to edit" (`scheduleMode` in `App.jsx` via `useUi()`, `clickMode` in `ScheduleGrid.jsx`): rows read as chips; clicking a row opens its selects (one row at a time, same select design, same typing = X / selected = counter behaviour, but an empty month shows no 0 counter, only the chevron; after Save the row is chips again so no counters); Cancel / Save apply to the open row and Save returns it to chips; with no Type T/X Mapping an opened Unit row shows one spanning message across its months ("No results found. Start by creating a Type T/X Mapping here." for A, "No Type T/X Mapping found." for B). Remove the toggle and the unused mode once one is chosen.
- **X - PREP** (Type X, Code PREP) Mapping: one Product Family, not scheduled, so never offered in the Schedule. One Mapping each for T/X and X - PREP; an option already mapped shows "Mapped" and is disabled. A future Code would add one more option (X - ABC) with no new field. Create Mapping has three fields: Type - Code, Activity Type, Category (equal width).
- **Chips**: every table chip (Mapping and Schedule) uses one fill, #2C2C2C (grey/900) with white text and no border (`.table-chip`), so there are no legends and no info icons. Table chips are 14px / 18px line height and the "Category A:" labels follow (14px); in the Mapping table Category lines and wrapped chip rows are 8px apart. Multi-select chips (`.multi-chip`) are #FFFFFF at 16% on the field.
- **Fixed** (Unit tab) is read-only and never involves a mapped Product Family (in Create Mapping the FIXED option is disabled with "Mapped to respective units"): each Unit holds its own Product (plain text like the Unit column, not a chip; column header "Fixed Product", left aligned) from the unmapped Product Family **FIXED** (FIXED01 to FIXED16, one per Unit, no overlaps), assigned in `initialDb.js`. `fixedPool` lists the Products of unmapped families; if a family later gets mapped, its Fixed Products are pruned like any other Schedule entry (and listed in the confirm dialog). The "No Mapping / Schedule" preset clears Fixed.
- Create/update/delete of Mappings and Product Families prune Schedule entries that no longer fit and list what is removed in the confirm dialog. Creating a Mapping with a new inline Product Family asks for confirmation.
- **Dots**: a new or saved row gets a #00DCFF row dot, cleared by clicking the row. A **tab dot** shows while any row under that tab has a dot (including the active tab) and disappears when the last one is cleared.
- After creating a Mapping from Schedule the user stays on Schedule; the snackbar CTA is skipped in that case.
- Delete Product Family dialog: title "Delete <name>"; with Schedule entries a "Mapped to O:" / "Mapped to T/X:" / "Mapped to X - PREP:" line (Type only, because the Activity Type · Category or Unit is in the table) above a two-column table (Unit or Activity Type · Category, Schedule; columns share the width equally); without Schedule entries no table and the line keeps the full label ("Mapped to O · Alpha · Category A", same labels as the Create Mapping options, no word "Type"). Then "will also remove it from Mapping and/or Schedule", the "whole Mapping will be deleted" note when it is the Mapping's last family, and the undo note.
- Delete Mapping dialog: the title names the Mapping ("Delete Type T/X Mapping", "Delete Type O Mapping", "Delete X - PREP Mapping"); Type O adds an "Activity Type <name>" line. The table (Unit or Activity Type · Category, Schedule, Product Family; no "Category A:" prefix in the Product Family column, a Type O family that is not scheduled shows its Activity Type · Category in the first column and "—" under Schedule) shows only when deleting removes Schedule entries; otherwise just "This action cannot be undone."

- **Toggle buttons** (`MuiToggleButton`: Schedule Unit / Activity Type, launcher toggles, month picker): text #FDFDFD selected or not; selected = #FDFDFD 16% fill and #FDFDFD 12% border (no cyan).

## Layout numbers
Modal 1600px (app width 1920). Month columns min 168, six visible; same widths on both Schedule tabs. Unit 80 / Fixed Product 150; Activity Type 160 / Category 160 (left aligned; only months centred). Mapping Type - Code column 220 (no separate Code column), no truncation. Toolbar 64px, row heights multiples of 4 (Schedule rows are at least 48px, also when every month is empty). Schedule and Product Family tables fill the background like the Mapping table when rows don't overflow.
